## 2. Document Processing & ETL

### SurfSense
- **ETL choices:** Docling (local, privacy-first), Unstructured.io (API), LlamaCloud (API).
- **Docling pipeline:** Downloads PDF → disables OCR → extracts text → applies `OverlapRefinery` (10% overlap, `suffix` method) → produces overlapping chunks.
- **Large doc handling:** Map-reduce with per-chunk LLM summaries → merged final summary.
- **Strength:** Flexibility — user picks their ETL service. Privacy-first with Docling running locally.

### DigiClassroom Pro
- **ETL choice:** PDF-Extract-Kit v1.0.0 — a full GPU-accelerated pipeline:
  - **Layout Detection:** DocLayout-YOLO for structure analysis
  - **OCR:** PaddleOCR with **148+ custom correction patterns** for Indian textbooks
  - **Formula Recognition:** UniMERNet for mathematical equations
  - **Table Extraction:** StructEqTable for complex tables
  - **TOC Extraction:** PyMuPDF-based Table of Contents parsing with 95% chapter confidence
- **1,138-line** Python extraction script with full GPU requirement.
- **Strength:** Dramatically deeper document understanding — layout-aware, formula-preserving, table-extracting. Purpose-built for NCERT textbooks.

> **Verdict:** DigiClassroom Pro's ETL is **significantly more sophisticated** for its domain. SurfSense is more flexible and privacy-friendly.

## 3. Chunking Strategy

### SurfSense
- Uses **Chonkie library** (open-source):
  - `RecursiveChunker` for general text
  - `CodeChunker` for source code
  - `OverlapRefinery` for boundary overlap (10% context)
- Chunk size = model's `max_seq_length` (auto-detected)
- Clean, minimal code — ~10 lines of config.

### DigiClassroom Pro
- **Custom 3-tier Multi-Level Chunker** (696 lines):
  1. **Section** (800–1200 tokens): Full topics
  2. **Paragraph** (200–400 tokens): Complete concepts
  3. **Atomic** (50–100 tokens): Single facts, definitions, formulas
- **GPT-4o-mini powered atomic extraction** with:
  - Enhanced educational prompts for formulas, numbers, and context
  - JSON parse retry with exponential backoff
  - Quality metrics tracking (formula preservation rate, numerical accuracy, context completeness)
  - Sentence-level fallback when LLM fails
- Full **parent-child-sibling hierarchy** between chunk levels.

> **Verdict:** DigiClassroom Pro's chunker is **far more advanced** — it's a hierarchical, LLM-powered, quality-tracked system. SurfSense's is simpler but production-ready and model-agnostic.

## 4. Embedding & Vector Search

### SurfSense
- **Embeddings:** `AutoEmbeddings.get_embeddings(MODEL)` — dynamically supports any model (OpenAI, local, Azure).
- **Storage:** pgvector inside PostgreSQL (single database for everything).
- **Hybrid Search:** Two PostgreSQL CTEs:
  1. `semantic_search_cte` using cosine distance (`<=>` operator)
  2. `keyword_search_cte` using `to_tsvector` / `plainto_tsquery`
  - Combined with `FULL OUTER JOIN` + RRF formula: `1.0 / (60 + rank)`
- **Validation:** 2000-dimension hard limit enforced at startup.
- **Strength:** Everything in PostgreSQL — one database, zero external dependencies, battle-tested.

### DigiClassroom Pro
- **Embeddings:** OpenAI `text-embedding-3-small` (3072 dimensions, hardcoded).
- **Storage:** Qdrant (dedicated vector DB with HNSW index).
- **Hybrid Search:** Dense vectors + BM25 sparse vectors sent to Qdrant with RRF fusion.
- **Sparse Vector Generator** (213 lines): Full BM25 implementation with:
  - Custom tokenizer with stop word removal
  - IDF calculation: [log((N - df + 0.5) / (df + 0.5) + 1)](file:///J:/Apps/DigiClassroom%20Pro/src/lib/ai/rag/multi-level-chunker.ts#668-691)
  - Length-normalized BM25 scoring (k1=1.5, b=0.75)
  - Vocabulary persistence (import/export)
- **A/B Testing:** Built-in embedding experiment framework for comparing variants.
- **Strength:** Qdrant is purpose-built for vector search with better HNSW performance at scale.

> **Verdict:** Both implement hybrid search with RRF, but via very different architectures. SurfSense's PostgreSQL-native approach is simpler; DigiClassroom's BM25+Qdrant is more textbook-correct and scalable for vector workloads.

## 5. Retrieval & Ranking Pipeline

### SurfSense
- **Pipeline:** Query → Embedding → Hybrid CTE → RRF Merge → Optional Reranker → Results
- **Reranking:** Optional, via the `rerankers` library (Pinecone, Cohere, etc.)
- **Concise:** ~358 lines for the entire retrieval module.

### DigiClassroom Pro
- **Pipeline (1,740 lines):** 
  1. Query Enhancement (auto-detect subject, expand terms)
  2. Smart Subject Filter (auto-correction when no results)
  3. Qdrant Hybrid Search (dense + BM25 sparse)
  4. Relevance Threshold Filtering
  5. **Cross-Encoder Reranking** (Xenova/ms-marco-MiniLM-L-6-v2, quantized)
  6. Educational Relevance Ranking (STEM boost, section-level boost)
  7. Content Validation (textbook fidelity scoring, knowledge gap detection)
  8. Multi-level Fallback (primary → relaxed → emergency → keyword)
- **Query Decomposition:** Complex multi-part queries are decomposed into sub-queries, searched independently, then synthesized with diversity-aware deduplication.
- **4-Strategy Hybrid Retrieval Engine** (675 lines):
  - Exact text matching (40% weight)
  - Semantic vector search (30% weight)
  - Entity-based retrieval (20% weight)
  - Structural retrieval (10% weight)
  - Query-type-aware weight adjustment (definitions boost exact, factual boost micro-chunks)

> **Verdict:** DigiClassroom Pro's retrieval is **vastly more complex** — 5x the code, 4 parallel strategies, cross-encoder reranking, query decomposition, and educational domain tuning. SurfSense is elegant and efficient but simpler.

- Provider-agnostic design (any LLM, any embedding model)

**DigiClassroom Pro Strengths:**
- Domain-specific prompt engineering is world-class
- Multi-layered fallback strategies show production experience
- Quality metrics tracking (formula preservation, numerical accuracy)

**DigiClassroom Pro Weaknesses:**

- Heavy coupling to OpenAI — switching providers would require significant refactoring
- Agent files are massive (45,000+ bytes each) with significant duplication across agents
- Cross-encoder implementation uses `feature-extraction` pipeline as a proxy (not a true cross-encoder)

## 9. Final Honest Assessment

### SurfSense is better when you need:
- A **general-purpose** AI knowledge base
- **Privacy-first** local operation (Ollama + Docling)
- **Multi-source** data aggregation (Slack, Notion, GitHub, etc.)
- **Provider flexibility** (swap LLMs without code changes)
- **Clean, maintainable** architecture for long-term development
- **Podcast generation** from documents

### DigiClassroom Pro is better when you need:
- **Education-specific** AI tutoring with curriculum alignment
- **Deep document understanding** (layout, formulas, tables, OCR)
- **Personalized student interactions** (name, grade, language, cognitive level)
- **Curriculum-scoped responses** with hallucination prevention
- **Advanced retrieval** (4-strategy hybrid, query decomposition, cross-encoder)
- **Indian education context** (CBSE/ICSE, bilingual, NCERT citations)
