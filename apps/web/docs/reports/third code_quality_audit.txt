## 2. Error Handling & Resilience

### SurfSense (Gold Standard) ⭐
```python
# app.py — Rate limiting with graceful Redis fallback
async def _check_rate_limit(request, max_requests, window_seconds, scope):
    try:
        redis_client = _get_rate_limit_redis()
        key = f"rate_limit:{scope}:{client_ip}"
        current = redis_client.incr(key)
        if current == 1:
            redis_client.expire(key, window_seconds)
        if current > max_requests:
            raise HTTPException(status_code=429, ...)
    except redis.ConnectionError:
        # Falls back to in-memory sliding window — app NEVER crashes
        _check_rate_limit_memory(client_ip, max_requests, window_seconds, scope)
```

- **Pattern**: Try external → fallback gracefully → never crash
- **Every** error handler has a specific exception type
- Consistent `HTTPException` with structured JSON responses
- [DocumentStatus](file:///J:/Apps/LLM/surfsense_backend/app/db.py#103-178) helper centralizes state machines

### DigiClassroom Pro ⚠️
```typescript
// Found in 16 agent files — generic catch-all pattern
} catch (error) {
    console.error('Agent execution failed:', error);
    // Sometimes returns empty string, sometimes throws, sometimes returns fallback
}
```

**Issues Found:**
- **50+ files** in `src/lib` contain `console.log` — should use structured logger
- Agent `catch` blocks are inconsistent: some return `""`, some throw, some return fallback text
- No custom error classes — all errors are generic `Error` or string messages
- `res: undefined as any` in tRPC route handler — unsafe type casting
- `as any` casts in tRPC routers (`sarvagya.ts` lines 88, 186)

> [!WARNING]
> **Scoring: SurfSense 9/10 → DigiClassroom Pro 5/10**
> Critical gap: no structured error hierarchy, inconsistent catch patterns, `console.log` everywhere instead of structured logging.

### Fix Priority
1. Create `src/lib/errors/` with custom error classes: `AgentError`, `RetrievalError`, `ValidationError`, `AuthError`
2. Replace all `console.log/error` with a logger (e.g., `pino` or `winston`)
3. Standardize agent error handling: always return a typed `AgentResult` with `success/error/metadata`
4. Eliminate all `as any` casts
