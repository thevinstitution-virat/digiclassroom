## Quick Rollback Commands

### Rollback Last Commit (All Changes):
git revert HEAD --no-edit
git push

### Rollback Specific File:
git checkout HEAD~1 -- path/to/file.ts
git add path/to/file.ts
git commit -m "Rollback: Restore specific file"
git push

### Rollback to Specific Commit:
git log --oneline  # Find commit hash
git revert <commit-hash> --no-edit
git push

### Nuclear Option (Reset to Before Cleanup):
# Create backup branch first!
git branch backup/before-cleanup
git push origin backup/before-cleanup

# Then reset (DANGEROUS - only if necessary)
git reset --hard HEAD~3  # Go back 3 commits
git push -f origin main  # Force push (use with caution)

---

## Prevention Strategy

Before ANY cleanup:

1. Create backup branch:
   git checkout -b backup/pre-cleanup-$(date +%Y%m%d)
   git push origin backup/pre-cleanup-$(date +%Y%m%d)

2. Tag current state:
   git tag cleanup-phase1-start
   git push --tags

3. Commit frequently:
   git commit -m "Phase 1.1: Remove redis cache stub"
   git commit -m "Phase 1.2: Archive documentation"
   git commit -m "Phase 1.3: Remove test scripts"

4. Test after each commit:
   npm run dev
   # Send test message
   # Verify no errors

5. Monitor for 24 hours:
   # Check logs for errors
   # Monitor performance metrics
   # Verify all agents working

---

## Recovery Timeline

If cleanup breaks production:

- 0-5 mins: Identify the issue (check logs, error messages)
- 5-10 mins: Execute rollback (git revert or git checkout)
- 10-15 mins: Verify rollback worked (test agents)
- 15-30 mins: Investigate root cause
- 30-60 mins: Fix and re-attempt cleanup (if safe)

Maximum downtime: 15 minutes (time to rollback and verify)
